## 5. Архитектура и полный процесс работы системы

### Старт системы и подготовка сервера

1. Администратор разворачивает сервер с установленным и запущенным n8n. 
2. После этого на сервере вручную выполняется скрипт server.sh. (server-setup.md)
3. Выполняется настройка n8n и его workflow (n8n-setup.md)

С этого момента сервер считается полностью подготовленным к приёму лабораторных работ.


### Работа на стороне студента (client.sh)

Студент получает набор учебных материалов (student-distribution.md) и скрипт client.sh.

После запуска client.sh выполняется следующий сценарий:

1. Проверяется наличие SSH-клиента; при отсутствии он устанавливается автоматически.
2. Создаётся локальный пользователь linuxoid, от имени которого выполняется лабораторная работа.
3. Настраивается SSH-доступ к серверу с использованием встроенного приватного ключа.
4. Устанавливается соединение с сервером и скачивается архив worklab.zip.
5. Шаблон лабораторной распаковывается в домашний каталог пользователя.
6. У студента запрашиваются персональные данные (ФИО и группа), которые сохраняются локально.
7. В файл .bashrc добавляется команда labserver — единая точка взаимодействия с сервером.

После выполнения этих шагов студент может приступать к выполнению лабораторной работы.

Для отправки результатов на проверку студент выполняет одну команду:

labserver --send-lab

### Приём и предварительная обработка работы на сервере

После вызова команды labserver --send-lab происходит следующее:

1. Домашний каталог студента архивируется на клиентской стороне.
2. Архив передаётся на сервер по SSH.
3. Срабатывает серверный скрипт on_connect_ssh.sh, запущенный через механизм forced-command.
4. На сервере определяется:

   * какой студент отправил работу (ФИО и группа);
   * номер текущей попытки.

#### Контроль количества попыток

Для каждого студента задан лимит попыток (например, 10).

* Если лимит исчерпан:

  * студент немедленно получает сообщение об отказе в проверке;
  * преподавателю отправляется уведомление через n8n;
  * дальнейшая обработка работы прекращается.

* Если лимит не превышен — работа принимается к проверке.

### Проверка лабораторной работы

При допуске работы к проверке:

1. Архив студента сохраняется в каталоге /home/admeen/verification.
2. Запускается скрипт run_verification.sh.
3. Скрипт поднимает Docker-контейнер с изолированной средой проверки.
4. В контейнере:

   * распаковывается архив лабораторной работы;
   * извлекается история команд студента (history);
   * запускается скрипт verification.sh.

Скрипт verification.sh проверяет:

* наличие и отсутствие файлов;
* корректность прав доступа;
* содержимое файлов;
* соответствие текущего состояния файловой системы условиям заданий.

Результаты проверки сохраняются в виде:

* отчёта с найденными ошибками;
* истории команд студента;
* архива текущего состояния файловой системы.

Содержимое отчёта сразу выводится студенту в терминал.

### Интеграция с n8n и работа преподавателя

После обновления отчётных файлов автоматически запускается n8n:

* обновляется общая сводка по всем студентам;
* фиксируются:

  * превышение лимита попыток;
  * успешная сдача лабораторной работы;
* успешно сданные работы проверяются на плагиат;
* формируется и отправляется отчёт преподавателю.

#### Что получает преподаватель

Преподавателю приходит письмо, содержащее:

* ФИО студента;
* группу;
* номер и дату попытки;
* количество оставшихся попыток;
* файл отчёта проверки;
* список подозрительно похожих работ (если есть).

При необходимости преподаватель может получить табличную сводку по всем студентам, включающую:

* ФИО и группы;
* историю попыток (дата, время, статус);
* отметки о возможном плагиате.
